# Round 13 — Clinician console: Log out + User-side switch (2026-10-11)

**Owner request:** "In clinician console there is no log out option, and it is totally out from the user console so that the clinician cannot see what is there in the user side. Make it so the clinician can also log out and go to the user side."

## What changed

### 1. New `StaffViewContext` (`src/context/StaffViewContext.tsx`)
- `personalView` flag + `setPersonalView`. Default `false` → clinician console for role `clinician`.
- Resets to console automatically when the signed-in account changes (covers sign-out → sign-in and account switching).

### 2. App.tsx — dual-view gate
- Clinician stack renders when `role === 'clinician' && !personalView`; otherwise the family stack (Home, AddPatient, PatientTabs, Settings, …).
- Family stack now also registers `ClinicianPatientList` + `ClinicianPatientDetail` (so parent-role admins can still open the clinician area from Home, as before).

### 3. Clinician console header (`ClinicianPatientListScreen`)
- **"User side" button** (people icon, bilingual: प्रयोगकर्ता पक्ष) → switches to the family view.
- **"Log out" button** (red-tinted chip, bilingual: लग आउट) → confirm dialog → `signOut()` (same hardened sign-out path as Settings, with local fallback).

### 4. Family side — way back
- **HomeScreen (empty state):** for role `clinician`, adds a "Clinician console" button → flips back to the console (admin console entry preserved).
- **HomeScreen (with patients):** staff card entry "Clinician area" renamed to "Clinician console"; for role `clinician` it flips the view back instead of pushing a screen.
- **SettingsScreen:** new "Clinician console" row (patient list & regimen approvals) under Staff section for role `clinician`.

## Behavior summary
| Who | Before | After |
|---|---|---|
| Clinician / full-access staff | Locked into the clinician console; no log out; no family side | Console by default; **User side** button → family view; **Log out** button; way back from Home/Settings |
| Parent | Family side only (unchanged) | Unchanged (admin entries unchanged) |

- The user side for a staff account is fully functional: Home lists only their own children; they can add their own child, log, etc.
- Sign-out uses the existing hardened `signOut` (server + local fallback).
